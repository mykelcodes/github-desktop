# First-release workflow contract

12 November 2026 · M0 baseline · DISC-01

These 20 scripts define the PRD workflow-coverage denominator. Run them as moderated manual acceptance scripts against the release app when their features are available. Their current execution status is **not run**. Definition of the scripts completes discovery work. Passing the scripts is tracked in the implementation milestones.

For each run record build/OS/CPU, role, fixture ID, steps completed, native or handoff outcome, elapsed time, failures, and an evidence link. A script passes natively only when every step and expected result passes inside the app, with the system browser permitted for authentication and an editor permitted for editing source. Each script contributes one point. Public 1.0 requires at least 18/20 native passes and every required PRD acceptance criterion. Record supported browser handoffs separately. Reset disposable fixtures between runs.

## Test cohort and fixture contract

Recruit ten moderated participants for beta acceptance. Seats 1–3 are individual developers with basic Git knowledge, seats 4–6 are team contributors who review PRs, seats 7–8 maintain protected repositories and use advanced history editing, seat 9 regularly uses VoiceOver, and seat 10 works primarily by keyboard. Include overlapping SSH/signing, private-repository and organization/SSO experience. Product owns recruitment and consent. These are recruitment criteria, with participant identities and session results still pending.

Use two dedicated GitHub accounts A/B and a disposable test organization. Prepare public and private repositories with the same display name across account contexts, an upstream/fork pair, a read-only collaborator, a restricted organization/SSO case, protected and queue-required branches, and an Actions workflow with inputs, failed jobs, logs and a small artifact. Keep production repositories outside the fixture set. Record actual host, repository IDs, grants, roles and restrictions in private session notes.

Local fixtures include a plain folder, empty Git repository, existing clone, unrelated remote history, missing/moved folder, nested folder, two worktrees, divergent branches, detached HEAD, merge and rebase conflicts, staged/unstaged/untracked/ignored files, binary content, renames, Unicode and unusual filenames, LFS and submodule repositories, SSH and signing identities. Use synthetic content. Performance fixtures contain 10,000 files and 100,000 commits.

## Screen map

Additional mandatory handoff checks cover unsupported deep links, advanced issue forms and queue-required merges. They must preserve context/drafts and open the exact destination. They are recorded separately from the 20 native workflow scores, and must pass before 1.0.

| Entry | Screens and commands |
| --- | --- |
| App shell | Welcome/sign-in, account switcher, sidebar, command palette, global Search, Inbox, My Work, Local Folders, saved workspaces, per-window context |
| Repository | Overview, README/tree/file/compare, Issues list/detail/composer, PR list/detail/review/checks/merge, Actions list/run/job/log/artifact |
| Local | Connect/clone/setup, checkout picker, Changes/stage/commit, History/detail/blame, Branches/tags/remotes/worktrees, stash, conflict resolution, rebase preview, operation/recovery timeline |
| Settings and recovery | Account/grant/transport/signing configuration, cache/draft export/erasure, helper trust, alerts, diagnostics preview, install/update and support |

The repository Local tab and the global Local Folders entry reach the same checkout state. Account, API identity, Git transport and commit author remain distinct concepts throughout the screens.

## Scope and staffing baseline

Keep all APP-01–APP-05, HUB-01–HUB-08, GIT-01–GIT-13 and NFR-01–NFR-07 requirements in the first public release. The table traces the functional journeys. NFR-01 additionally requires measured launch, memory and idle CPU evidence. NFR-02 additionally requires full keyboard/VoiceOver sessions. NFR-06 additionally requires notarization, update, migration and platform-matrix evidence. NFR-07 additionally requires recovery retention and support checks. The implementation backlog owns those validations independently of the 20-script score.

Exclude native Projects/Discussions administration, organization/enterprise administration, AI assistance, sparse-checkout UI, bisect automation, patch-mail workflows and repository-wide history filtering from 1.0 as specified in the PRD. Preserve their browser handoffs and later capability inventory. Advanced Git stays in 1.0.

Use the delivery plan's two-engineer baseline, with product/design and QA/security support, until actual availability is supplied. An auth broker needs an operational owner. The current 66–102 engineer-week estimate plus contingency remains provisional while M0 blockers remain. Record actual throughput before selecting dates.
